\chapter{はじめに}

「ロボットを動かしてみたい。でも、何から始めればいいのかわからない」。
本書は、そんな人のための入門書です。

ロボットのソフトウェア開発の世界では、Linux という OS の上で、ROS 2 というソフトウェアを使ってロボットを動かすのが一般的になっています。
ところが、いざ始めようとすると、黒い画面にコマンドを打ち込む操作、聞き慣れない専門用語、英語ばかりの資料が次々と現れて、最初の一歩でつまずいてしまう人が少なくありません。
本書は、その最初の一歩を一緒に踏み出すための本です。

\section*{本書の目的}

本書には、次の 4 つの目的があります。

\begin{description}
  \item[Linux に慣れる]
    ロボット開発の土台となる Linux を、怖がらずに使えるようになることを目指します。
    ターミナルでコマンドを入力し、ファイルを操作し、ソフトウェアをインストールするといった、日常的な操作を一通り身につけます。
  \item[ROS 2 を使うための土台を作る]
    ROS 2 を使うには、Linux だけでなく、エディタ、Git、ネットワーク、Python といった周辺の知識が必要です。
    本書では、これらを ROS 2 に入る前に順番に学び、ROS 2 の学習でつまずかないための土台を作ります。
  \item[「最初に何をすればいいか」の道しるべになる]
    ロボット開発を始めたばかりのころは、何から手を付ければよいのかもわからないものです。
    本書は、パソコンの準備から始めて、どの順番で何を学べばよいのかを示す道しるべとして使えるように構成しています。
  \item[調べるためのキーワードを知る]
    ロボット開発では、本に書かれていないことに必ず出会います。
    そのときに頼りになるのが、インターネットでの検索です。
    ただし、検索するには「何という言葉で調べればよいか」を知っている必要があります。
    本書では、重要な用語を太字で示し、付録\ref{app:glossary}の用語集にもまとめています。
    本書を読み終えたとき、困ったことがあっても、自分で適切なキーワードを使って調べられるようになっていることも、本書の大切な目的の 1 つです。
\end{description}

そして最終的には、これらの土台の上で Python と ROS 2 を実際に触り、自分の手でロボットを動かせるようになることを目指します。

\section*{対象読者}

本書は、次のような人を対象にしています。

\begin{itemize}
  \item ふだんパソコンは使っているが、Web ブラウザや、大学のレポートを書くための文書作成ソフトくらいしか使ったことがない人
  \item 大学に入って、初めて自分のパソコンを持った人
  \item 研究室やロボットのチームに入り、Linux や ROS を使う必要が出てきた人
\end{itemize}

プログラミングの経験や、Linux を使った経験は必要ありません。
本書は「コンピュータとは何か」という話から始めて、ターミナルの使い方、Python の基本、そして ROS 2 でロボットを動かすところまでを、順を追って丁寧に説明します。
パソコンの電源を入れて、Web ブラウザでインターネットを見たり、ファイルを保存したりできれば、それで十分です。

\section*{本書の構成}

本書は、次の 5 つの部と、補章・付録でできています。

\begin{description}
  \item[第I部 Linux 入門] コンピュータのしくみ、Linux とは何か、Linux の内側のしくみを学び、VirtualBox で Ubuntu の環境を用意します。
  \item[第II部 コマンドラインの基本] ターミナルとシェルの使い方、ファイルの操作、権限、テキスト処理、プロセス、環境変数、シェルスクリプトを学びます。
  \item[第III部 開発のための周辺ツール] パッケージ管理、エディタ（VS Code など）、Git、ネットワークとリモート操作、Docker を学びます。
  \item[第IV部 Python 入門] ROS 2 のプログラムを書くために必要な Python の基本を、練習問題を解きながら学びます。
  \item[第V部 ROS 2 入門] ROS 2 のしくみを理解し、Python でノードを書き、シミュレーションや実際のロボットを動かします。
\end{description}

補章では、本編の内容を別の方法・別の書き方で解説しています（Docker のコンテナを使った ROS 2 の開発環境、C++ でのノードの書き方と、XML での launch ファイルの書き方）。
付録には、コマンドの早見表、よく使うキー操作、Python の練習問題の解答例、トラブルシューティング、用語集、参考文献をまとめています。

\section*{本書の読み方}

本書は、\textbf{実際にパソコンを使って、自分の手を動かしながら読む}ことを前提にしています。
プログラミングや Linux の操作は、読んだだけではなかなか身につきません。
本書に出てくるコマンドやプログラムを、自分のパソコンで実際に入力し、どのような結果になるのかを確かめながら読み進めてください。
うまくいかなかったときに、エラーメッセージを読み、原因を考え、調べて直すという経験こそが、何よりの力になります。

\begin{itemize}
  \item \textbf{はじめから順番に読む}：
    各章は、それより前の章の内容を使って説明しています。
    初めての人は、\ref{chap:computer}章から順番に読み進めてください。
    すでに知っている内容は、章の冒頭の「この章で学ぶこと」と、章末の「この章のまとめ」を確認して、先に進んでも構いません。
  \item \textbf{環境を用意する}：
    \ref{chap:what_is_linux}章で、VirtualBox を使って、自分のパソコンの中に Ubuntu の環境を作ります。
    Windows でも macOS でも、同じ手順で本書の内容を試せます。
  \item \textbf{練習問題に取り組む}：
    第IV部には練習問題があります。
    解答例は付録\ref{app:python-answers}にまとめてあります。見る前に、まずは自分で考えて書いてみましょう。
  \item \textbf{わからない言葉は調べる}：
    わからない言葉が出てきたら、付録\ref{app:glossary}の用語集や、インターネットで調べてみましょう。
    調べる力を身につけることも、本書で練習してほしいことの 1 つです。
\end{itemize}


\section*{本書の表記}

本書には、次の 2 種類の枠が出てきます。
どちらも、\textbf{実際に手を動かすところ}です。
読むだけで済ませずに、自分のコンピュータで入力し、結果を確かめながら読み進めてください。

\subsection*{ターミナルの枠}

ウィンドウのような見た目の枠は、ターミナルで入力するコマンドと、その実行結果を表しています。
本文中でターミナルの枠が登場した場合は、実際にターミナルを開いたあと、コマンドを入力して、同じ結果になるかを確かめましょう。

\begin{terminal}[ターミナルの枠の例]
$ echo "Hello, robot!"
Hello, robot!
$ cd ~/practice
~/practice$ ls
memo.txt
\end{terminal}

\begin{itemize}
  \item \cmd{\$} から始まる行は、一般ユーザで実行するコマンドです。\cmd{\$} は入力せず、その後ろの部分だけを入力して \key{Enter} を押します。
  \item \cmd{\textasciitilde/practice\$ ls} のように、\cmd{\$} の前にパスが書かれている行は、そのディレクトリ（ここではホームディレクトリの中の \cmd{practice}）で実行するコマンドです。その前に \cmd{cd} で移動したときに、今どこにいるのかがわかるように書いています。パスと \cmd{\$} は入力しません。
  \item \cmd{\#} から始まる行は、root 権限で実行するコマンドです。
  \item \cmd{\$} や \cmd{\#} が付いていない行は、コマンドの実行結果です（入力しません）。長い実行結果は、途中を \cmd{...} で省略しています。
  \item \cmd{<ファイル名>} のように山括弧で囲まれた部分は、自分の環境に合わせて置き換えてください。
\end{itemize}

紺色のタイトルバーと点線の枠で、タイトルが「例：」で始まる枠は、\textbf{表示例}です。
まだ作っていないファイルや、つながっていない機器を使う例、実行すると困ることがある例（動いているプログラムを止めるコマンドなど）、コマンドの書き方を説明するための例などを表しています。
表示例は、読んで内容を理解するためのもので、その場で入力する必要はありません。

\begin{termexample}[表示例の枠の例]
$ kill <プロセスの番号>
\end{termexample}

実行結果に出てくる名前や数字は、読者の環境によって変わることがあります。
たとえば、本書では、ユーザの名前を \cmd{user}、コンピュータの名前（ホスト名）を \cmd{robot} として表示しています（\cmd{/home/user} や \cmd{user@robot} など）。
自分の環境では、Ubuntu をインストールしたときに決めた名前に読み替えてください。
日付や時刻、ファイルの大きさ、プロセスの番号なども、表示のとおりにはならないのが普通です。

\subsection*{ソースコードの枠}

行番号の付いた枠は、プログラムや設定ファイルの中身（ソースコード）を表しています。
エディタ（\ref{sec:files-edit}節のテキストエディターや、\ref{chap:editor}章の VS Code など）でファイルを作って同じ内容を書き、保存してから実行してみましょう。
左端の行番号は説明のためのもので、入力しません。

\begin{codelisting}[style=python]{ソースコードの枠の例（hello.py）}{lst:preface-example}
name = "robot"
print(f"Hello, {name}!")
\end{codelisting}

枠の上に書かれた \cmd{hello.py} のような名前は、保存するときのファイル名の例です。
